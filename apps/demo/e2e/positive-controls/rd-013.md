# 양성 대조(DELTA-05)

브라우저 확인이 실제로 자동 들여쓰기 배선을 보는지, `packages/pyodide-repl/src/terminal/auto-indent.ts`를
임시로 망가뜨려 실패를 확인한 뒤 원복했다. `pnpm --filter demo dev`는 vite dev의 `development` export
조건(TRP-001)을 쓰므로 소스를 고친 뒤 **서버를 재시작**해야 반영된다(HMR만으로는 `createAutoIndent`
클로저가 새로 만들어지지 않을 때가 있었다 — RD-005 메모와 같은 이유).

절차마다: ① 편집 → ② `pkill -f "pnpm --filter demo dev"` 후 재기동 → ③ 대상 절 실행 → ④ 실패 확인 →
⑤ `git diff`로 원복 확인 → ⑥ 서버 재기동 → ⑦ 전체 26개 재확인(GREEN).

## 양성 대조 ①: `readOptions`에서 `prefill`을 뺀다

`auto-indent.ts`의 `readOptions` 두 반환문에서 `prefill: next.indentation`을 빼고(`pending===undefined`
분기는 원래도 `prefill`이 없어 그대로) `onKey`만 돌려주게 바꿨다.

결과(`ONLY=prefill,shift,unit,backspace`, 13개 중 5개 통과):

- 실패(8): `prefill` 3개 전부, `unit` 3개 전부, `backspace`의 `C2`·`C3`(빈 줄 종료·8→4칸 검사가 프리필에
  기대는 부분).
- 통과(5, 오탐 아님— 프리필과 무관): `backspace C1`(빈 버퍼에서 Backspace는 애초에 no-op이라 커서 열이
  우연히 그대로 4다)·`C4`(애초에 실패를 기대하는 시험이라 프리필 유무와 무관)·`shift F1`·`F2`.
  **계획 문구("prefill·shift·unit 절이 실패")와 달리 `shift`는 이 변이로 죽지 않는다** — Shift+Enter의
  들여쓰기는 `onKey`(`editInsert`)만으로 계산되고 `prefill` 필드를 읽지 않는다(코드 확인:
  `createAutoIndent`의 `onKey` 클로저는 `pendingBlock`·`getLine()`·`getCursor()`만 쓴다). 아래 결정 참고.

## 양성 대조 ②: `onKey`를 넘기지 않는다

같은 두 반환문에서 `onKey`도 빼(빈 객체 `{}`/`{ prefill }`만 돌려줌) `onKey`가 아예 전달되지 않게 했다.

결과(전체 26개 중 12개 통과, 14개 실패):

- 실패: `backspace` 3/4(`C1`·`C3`·`C4`), `unit` 2/3(`D1`·`D2`), `shift` 2/2, `alt` 2/2,
  `cancel` 4/6(`G1`·`D1`·`D2`·`D3`) — 전부 Backspace 단위 삭제 또는 Shift/Alt+Enter 들여쓰기(`onKey`)에
  기대는 시험.
- 통과(12, 오탐 아님 — `onKey`와 무관): `prefill` 3개(프리필 자체는 `readOptions`가 직접 채운다),
  `backspace C2`·`unit D3`(우연히 이 변이에서도 같은 결과가 나오는 경로 — 예: `D3`는 리셋 뒤 첫
  `if True:` 프리필만 보고 Backspace·Shift+Enter를 안 씀), `history E1`, `paste` 2개, `cancel C1`,
  `input` 2개, `multiline-shift`는 실제로는 실패 목록에 있다(위 표 참고, 이 문단은 생존 쪽만 요약).

## 결정

- 계획서(DELTA-05.md)는 양성 대조 ①이 `prefill`·`shift`·`unit` 절을 깨뜨린다고 적었지만, 실측 결과
  `shift`(F1·F2)는 이 변이로 죽지 않았다. 원인은 `createAutoIndent`의 모듈 경계(DELTA-04 확정 12,
  "정책 객체")가 프리필과 `onKey`를 독립된 값으로 계산해서다 — Shift+Enter는 항상 **현재 줄 + pending을
  합친 값**을 `onKey` 안에서 새로 계산하지, `readOptions`가 미리 채운 `prefill` 문자열을 읽지 않는다.
  계획 문구를 고치지 않고(계획서는 그릴링 확정 시점의 예상이라 소급 수정하지 않는다) 이 파일에 실측을
  남긴다. 두 변이를 합치면(①+②) `prefill`·`onKey` 양쪽에 의존하는 시험이 모두 최소 하나의 대조에서
  죽어 배선 전체가 커버된다.
