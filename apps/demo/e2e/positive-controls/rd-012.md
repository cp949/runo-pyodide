# RD-012 양성 대조 2건

확인 스크립트(`tla-check.mjs`·`index.test.ts`)가 실제로 실패를 잡아내는지, 정상 상태를 항상 통과시키는
관대한 판정이 아닌지 확인한다.

## 대조 ①: 스위치 OFF에서 `await`는 SyntaxError

`tla-check.mjs`의 `scenario` 절 첫 단계("OFF에서 `await asyncio.sleep(1)`은 SyntaxError 행")가 그 자체로
대조다 — 코드를 건드리지 않고, 데모의 기본 상태(체크박스 꺼짐)에서 `SyntaxError: 'await' outside
function` 행이 실제로 나오는지를 매 실행마다 확인한다. `verify/results/tla-dev.json`(dev·preview 둘 다)에서
PASS.

## 대조 ②: `session.ts`의 프레임 값을 `false` 리터럴로 되돌리면 실패해야 한다

`packages/pyodide-repl/src/session.ts`의 `topLevelAwait,`(프레임 필드)를 `topLevelAwait: false, //
POSITIVE-CONTROL-2: 원복 예정`으로 바꿔 옵션이 프레임에 실리지 않게 만든 뒤:

- 단위 시험(`pnpm --filter @cp949/runo-pyodide-repl test -- index.test.ts`): `top-level await 옵션(RD-012)`
  6건 중 4건 실패(①③④⑤ — `topLevelAwait: true`가 프레임에 반영되지 않고 sticky도 항상 `false`).
  로그: `verify/positive-control-2-unit.log`.
- 브라우저(`pnpm --filter @cp949/runo-pyodide-repl build` → dev 재시작(TRP-007) →
  `ONLY=초기,scenario node tla-check.mjs http://localhost:5173`): `scenario` 두 번째 단계("스위치 ON → 리셋 →
  같은 줄이 오류 없이 복귀")가 `SyntaxError가 남아 있다(TLA가 실제로 켜지지 않았다)`로 실패. 로그:
  `verify/positive-control-2-browser.log`.

원복(`topLevelAwait,`로 되돌림) → 코어 재빌드 → dev/preview 재시작 → `index.test.ts` 695건 전부 GREEN,
`tla-check.mjs` dev 16/16 + preview(`scenario`) 4/4 GREEN 복귀 확인(`verify/results/tla-dev.json`).

### 발견: 대조 도중 `scenario` 절 두 번째 단계의 판정 구멍을 찾아 고쳤다

처음 작성한 판정은 "트레이스백 0개 + `waitPrompt` 5초 이내 복귀"만 봤다 — `await asyncio.sleep(1)`이
SyntaxError로 **즉시** 끝나도 트레이스백은 안 나고 프롬프트도 곧바로 돌아오므로 이 판정을 그대로
통과시켰다(대조 ② 최초 실행에서 발견, `elapsed` 110ms로 비정상적으로 빠른데도 PASS). 두 가지를 추가했다:
최근 6행(`tail(6)`, 스크롤백 전체가 아니라 — 앞 절의 SyntaxError 문구가 남아 있어 전체 검사로는 이번
실행의 문구인지 구분 못 한다)에 `SyntaxError` 문자열이 없어야 하고, 복귀까지 걸린 시간이 500ms 이상이어야
한다(`await asyncio.sleep(1)`이 실제로 돌면 ~1초, SyntaxError면 수십~수백ms). 고친 뒤 재실행해 대조 ②가
정확히 이 절에서 실패함을 확인했다(위 로그).
