# writing-style

소스·시험·e2e 주석과 `docs/` 문서를 쓰고 고치는 규칙. 기준은 커밋 `76ae502`("소스·시험 주석과 설계 문서를 간결한 규칙으로 정비")다. 새 주석·문서는 처음부터 이 규칙으로 쓴다.

## 적용 대상

| 대상      | 예                                                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------ |
| 소스 주석 | `packages/*/src`, `apps/*/src`, `.py` 파일                                                                   |
| 시험 주석 | `packages/*/test`, `apps/demo/e2e`                                                                           |
| 문서      | `docs/design`·`docs/adr`·`docs/traps`·`docs/agents`, `DESIGN.md`, `README.md`, e2e `README.md`·`BASELINE.md` |

## 공통 문장 규칙

- 언어: 한국어. 식별자·명령어·에러 메시지는 원문 그대로 둔다.
- 종결: `~한다`체. 명사구 종결은 목록 항목과 표 셀에서 허용한다.
- 한 문장에 한 사실만 담는다.
- 이유·결과·예외를 `—`, `~하므로`, `~해서`로 이어 붙인 긴 문장은 나눈다.
- 나열·순서·조건 분기는 산문 대신 목록으로 쓴다.
- 표 셀도 한 문장으로 쓴다.
- 확인한 사실만 쓴다. 코드를 읽지 않고 설명하지 않는다.

나눔 예:

```text
전: `TextDecoder`는 SharedArrayBuffer 뷰를 받지 않는 브라우저가 있어 복사한 뒤 디코드한다. STATE·데이터는 바꾸지 않는다.
후: 현재 READY 청크(바이트·마지막 여부)를 읽는다. STATE·데이터는 바꾸지 않는다.
    `TextDecoder`가 SharedArrayBuffer 뷰를 받지 않는 브라우저가 있어 바이트를 복사해 돌려준다.
```

목록 분해 예:

```text
전: 배치: 제어 `Int32Array(4)` = [STATE, BYTE_LENGTH, FLAGS, 예약] + 데이터 `Uint8Array(CAPACITY)`. growable `SharedArrayBuffer`는 쓰지 않고 고정 할당한다.
후: 배치:
    - 제어 `Int32Array(4)` = [STATE, BYTE_LENGTH, FLAGS, 예약].
    - 데이터 `Uint8Array(CAPACITY)`.
    - growable `SharedArrayBuffer`는 쓰지 않고 고정 할당한다.
```

## 소스 주석

### 무엇을 쓰나

- 파일 머리 블록: 파일의 역할, 규칙이 사는 문서 절, 파일 안 함수들이 공유하는 전제.
- export 선언마다 JSDoc 한 개: `interface`·`type`·`function`·`const`.
- 인터페이스 필드·메서드마다 한 줄 JSDoc. 필드 사이는 빈 줄로 띄운다.
- 코드만으로 안 보이는 것: 이유, 불변식, 호출 순서, 부수 효과, 알려진 한계.
- 코드가 말하는 것은 쓰지 않는다. 이름을 되풀이하는 주석은 지운다.

### 형태

- 첫 문장에 동작을 쓴다. 이어서 조건·부수 효과·이유를 한 문장씩 쓴다.
- 문장 셋 이상이거나 분기가 있으면 목록으로 바꾼다.
- 한 줄로 끝나는 주석은 `/** ... */` 한 줄로 쓴다.
- 여러 줄은 `*` 시작 블록으로 쓴다. 줄 길이는 대략 120자 안쪽이다.
- 선언 밖 지역 설명(함수 안, 시험 `setup` 안 필드)은 `//`로 쓴다. JSDoc은 선언에만 붙인다.
- 규칙의 출처는 문서 절 번호로 가리킨다: `규칙은 docs/design/01-protocols.md 2.2.` 문장 끝에 둔다.

```ts
/**
 * 감시 타이머(03-ctrl-c.md 2.5).
 * JSPI로 정지한 대기 중에는 Python이 돌지 않는다. 폴링이 없다.
 * 이 타이머가 20ms 간격으로 버퍼를 엿보고, 정지한 대기가 있으면 `interruptIdle()`로 깨운다.
 *
 * 한 틱의 규칙:
 * - 엿보기: `hasPending()`이 거짓이면 아무것도 하지 않는다.
 * - 소비: `interruptIdle()`이 참일 때만 `consume()`한다.
 */
export interface InterruptWatchDeps {
  /** Python `interrupt_idle`. 정지한 실행을 깨웠으면 참(부른 쪽이 소비·ack한다). */
  interruptIdle(): boolean;

  /** SIGINT 슬롯이 전달 대기(2)인가 */
  hasPending(): boolean;
}
```

### 시험 주석

- 파일 머리 블록: 무엇을 시험하나, 어떤 환경에서(실제 worker·jsdom·가짜 터미널), 규칙 절 번호.
- `describe` 앞 `//` 블록: 그 묶음이 고정하는 결함이나 계약, 시험이 결정적인 이유.
- 이름 있는 헬퍼 함수: JSDoc 한 개. 시험 본문 안 지역 헬퍼는 `//`.
- 시험 제목(`it`·`describe`): 기존 제목을 바꾸지 않는다. 제목은 이력·변이 검사가 가리킨다.
- 상수를 일부러 import하지 않고 리터럴로 두면 그 이유를 쓴다(값이 바뀌면 시험이 실패하게 한다).

### e2e 스크립트

- 머리 주석: 어떤 RD를 검증하나, 실행 순서와 그 순서의 이유, 사용법, 기준 리터럴의 출처.
- 시간 판정(고정 대기·ms 상한)은 `docs/design/09-testing.md` 9.7을 링크로 가리키고 다시 서술하지 않는다.
- 사용법·환경변수는 `apps/demo/e2e/README.md`가 원천이다.

## 참조 표기

허용:

| 표기                                         | 뜻                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------ |
| `docs/design/NN-*.md N.M` 또는 `NN-*.md N.M` | 규칙이 사는 절                                                     |
| `ADR-NNNN`                                   | `docs/adr/`의 결정                                                 |
| `RD-NNN`                                     | 출처·검증 대상 항목(`ROADMAP.md`, `docs/history/first-roadmap.md`) |
| `TRAP-NN`                                    | `docs/design/11-known-traps.md`의 이관 함정                        |
| `TRP-NNN`                                    | `docs/traps/`의 새 함정                                            |
| `GitHub 이슈 #N`                             | 이슈 트래커 항목                                                   |

금지 — 저장소에 남지 않는 곳을 가리키기 때문이다:

| 표기                                                  | 대신                                               |
| ----------------------------------------------------- | -------------------------------------------------- |
| `DELTA-NN`, `DELTA-NN 2차 정정`                       | 지운다. 남길 내용이 있으면 결과만 쓴다(예: "실측") |
| `_works/…` 경로                                       | 지운다. `_works/`는 `.gitignore` 대상이다          |
| `.scratch/…` 경로                                     | 지운다. 이슈면 이슈 번호로 가리킨다                |
| 없는 파일(`design.md`, `skipped-ids.md`, `checklist`) | 지운다. 근거는 문장 안에 쓴다                      |
| 이전 구현 함정 번호 `TRP-0NN`(원본)                   | `TRAP-NN`(11-known-traps.md의 식별자)              |

- 참조 문서·경로는 존재를 확인한 뒤 쓴다. 절 번호가 바뀌면 참조도 같이 고친다.
- "계획서에 따르면", "체크리스트가 밝힌 대로" 같은 소멸한 문서 인용은 근거 문장으로 바꾼다.

## 설계 문서

- 규칙·상수는 한 곳에만 쓴다. 다른 곳은 절 번호로 링크한다.
- 규칙·상수를 바꾸면 해당 절과 `docs/design/10-parity-deviations.md`를 함께 고친다.
- `docs/design/11-known-traps.md`는 이관본이다. 새 함정은 `docs/traps/`에 쓴다.
- 절 번호는 읽기 순서다. 새 절은 끝 번호 다음에 붙인다.
- 개수·시간·바이트 같은 수치는 실측 값을 쓴다. 추정치를 쓰면 추정이라고 밝힌다.
- 이유 문장 하나에 결정·근거·기각안을 이어 붙이지 않는다. 목록 항목 하나에 사실 하나씩 쓴다.
- 실패 복구 표 같은 표 셀은 조치를 문장 단위로 끊는다.
- ADR은 결정과 근거를 자체로 완결되게 쓴다. 병합 뒤 사라지는 작업 문서에 의지하지 않는다.
- 진행 순서·번호가 있는 절차는 번호 목록을 쓰고, 항목 안 부연은 하위 목록으로 내린다.

## 고칠 때

1. 주석을 다시 쓰기 전에 대상 코드를 읽는다. 설명이 코드와 다르면 코드에 맞춰 고친다.
2. 틀린 설명을 찾으면 문체만 바꾸지 않고 내용을 바로잡는다. 커밋 메시지에 밝힌다.
3. 고친 수치는 다시 센다(예: L0 시험 개수는 `pnpm test`로 확인한다).
4. 문체만 바꾸는 커밋에서는 코드 동작을 바꾸지 않는다. 이름·로직 변경은 별도 커밋으로 분리한다.
5. 시험 제목은 그대로 둔다.

## 검증

| 명령                | 확인                                                |
| ------------------- | --------------------------------------------------- |
| `pnpm format:check` | prettier. 표 열 정렬 포함. `pnpm format`으로 고친다 |
| `pnpm lint`         | eslint                                              |
| `pnpm check-types`  | 타입. 주석 편집이 코드를 깨지 않았는지              |
| `pnpm test`         | L0. 주석 편집 뒤에도 통과해야 한다                  |

- 금지 표기 잔존 검사(출력이 없어야 한다): `grep -rn "DELTA-[0-9]" apps/*/src apps/*/e2e packages/*/src packages/*/test docs/design docs/adr docs/traps --exclude-dir=results`.
- `docs/agents/rubber-workflow.md`와 `docs/history/`는 DELTA를 절차 용어·이력으로 쓴다. 검사 대상이 아니다.
