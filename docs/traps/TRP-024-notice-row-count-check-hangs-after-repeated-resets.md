# TRP-024 안내 줄 개수로 "다시 준비됐다"를 판정하면 여러 번 반복한 뒤 무한 대기한다

- 상태: ACTIVE
- 적용 조건: 같은 페이지에서 세션 리셋(또는 그와 비슷한 "화면에 같은 안내 문구가 반복해서 찍히는" 동작)을 여러 번 반복하며, 각 회차의 완료를 "그 문구가 화면에 몇 번 나왔는지"(`rows().filter(...).length`)로 판정하는 브라우저 하니스.

## 오해하기 쉬운 신호

- 처음 몇 번(RD-010 실측: 3번째까지)은 각 ~1.3초로 정상 통과하다가, 어느 회차부터 긴 타임아웃(60초를 줘도)을 줘도 절대 통과하지 못한다.
- 타임아웃으로 던지는 오류 메시지 자체가 담은 화면 스냅숏에는 이미 기대하던 새 문구와 그 뒤 상태가 멀쩡히 보인다 — "조건이 아직 거짓"이라는 오류인데 화면은 이미 조건을 만족한 것처럼 보여, 판정 로직이 아니라 타이밍·배선을 먼저 의심하게 된다.

## 원인

xterm.js는 뷰포트(기본 24행)를 벗어난 행을 `.xterm-rows > div`의 실제 DOM 자식으로 유지하지 않는다(가상 스크롤백은 별도 내부 버퍼이고, 사용자가 실제로 스크롤을 올리지 않는 한 DOM에는 없다). 반복 동작으로 화면이 계속 길어지면 이전 회차의 문구가 뷰포트 밖으로 밀려 DOM에서 사라진다. "지금 보이는 문구 개수"는 그래서 매 회차 단조 증가하지 않는다 — 옛 것 하나가 빠지고 새것 하나가 들어와 개수가 이전과 같아지면 그 순간부터 "개수가 늘었다"라는 조건은 영원히 참이 되지 않는다.

TRP-008과 근본 원인(뷰포트 밖 DOM 소실)은 같지만 실패 형태가 다르다 — TRP-008은 "없다" 판정이 스크롤 때문에 거짓양성(조용히 통과)으로 새는 경우이고, 이 트랩은 "늘었다"(개수 증가) 판정이 스크롤 때문에 영원히 거짓으로 남아 멈추는(타임아웃) 경우다.

## 탐지/회피

- 회피: 반복되는 문구·행 개수 대신, 스크롤과 무관한 단일 상태 엘리먼트(예: `data-testid="status"`의 텍스트 전이, `loading` → `ready`/`load-failed`)로 "이번 회차가 끝났다"를 판정한다.
- 탐지: 반복 횟수를 늘려(예 N=10) 실행해 본다 — 1~3회차는 통과하고 그 뒤부터 막히면 이 트랩이다.
