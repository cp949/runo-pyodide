# TRP-006 화면 행 텍스트만 비교하면 출력 끝의 여분 빈 줄을 놓친다(커서 행을 봐야 한다)

- 상태: ACTIVE
- 적용 조건: Playwright로 xterm 화면의 마지막 출력 뒤 개행 수를 확인하는 하니스(`.xterm-rows > div` 행 텍스트 비교). 배너·값 에코·트레이스백·stderr 뒤 "빈 줄이 없다"를 검증할 때.

## 오해하기 쉬운 신호

- 행 텍스트 배열에서 빈 행을 걸러내거나 `slice(n).every(r => r === "")`로 끝을 보면, `err` 뒤에 개행이 하나 더 붙어도 결과가 같다. 텍스트 행 목록이 `["…배너", "…", "100%", "err"]`로 동일하다.
- 여분 개행은 화면의 글자가 아니라 커서 위치만 바꾼다. 스크린샷에서도 커서 블록의 위치로만 드러난다.

## 원인

`.xterm-rows > div`의 `textContent`는 셀 문자만 담는다. 개행으로 밀린 빈 행은 텍스트가 `""`인 채 원래 있던 빈 행과 구별되지 않는다(24행 터미널의 아래쪽 행은 항상 `""`).

## 탐지/회피

- 회피: 커서가 있는 행의 인덱스(`.xterm-cursor`가 든 `.xterm-rows > div`의 위치)를 단언한다. 예: 배너 2행 + `100%` + `err` 다음이면 커서 행은 4다. xterm 6 DOM 렌더러에서 `.xterm-cursor`가 있는 행을 찾을 수 있었다(Chromium 148 headless, 터미널이 포커스된 상태에서만 확인. 포커스를 잃은 상태의 클래스는 확인하지 않았다).
- 탐지: `packages/pyodide-terminal/src/sinks.ts`의 `writeErrorRaw`를 `print` → `println`으로 바꿔 하니스를 돌린다. 텍스트 행은 그대로이고 커서 행이 4 → 6으로 바뀌어야 하니스가 실패한다(RD-004 브라우저 확인에서 이 변이로 확인).
