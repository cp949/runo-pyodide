# TRP-077 벤더 폭 계산이 CSI 사설 접두를 파라미터로 받지 않으면 커서 숨김 시퀀스의 뒷글자가 폭 3으로 세어진다

- 상태: ACTIVE
- 적용 조건: 벤더 `packages/xterm-readline/src/tty.ts`의 `width()`(`calculatePosition`이 쓴다)를 고치거나 업스트림 변경을 수동 diff로 가져올 때, 프롬프트·배경 출력 접두에 CSI 시퀀스(`\x1b[?25l` 등 사설 접두 `?`·`>`·`=`·`<`나 중간 바이트가 든 것)를 싣는 코드·시험을 쓸 때.

## 오해하기 쉬운 신호

- 화면 출력은 정상이다. 터미널이 시퀀스를 스스로 해석하므로 `50%` 같은 본문은 제대로 보이고, 어긋나는 것은 벤더가 계산한 커서 열뿐이다(접두 `\x1b[?25l50%` + 입력 `> abc`에서 기대 8, 폭 계산이 세면 11). 편집 재그리기(Backspace·줄 중간 삽입)에서만 커서 위치와 지우기 행 수가 틀어진다.
- SGR(`\x1b[31m`)·`;`·숫자만 든 시퀀스는 원래도 맞았으므로 기존 시험이 모두 통과한다.
- 벤더 시험 도구 `VTerm`(`src/vterm.ts`)은 CSI 사설 접두를 `?`만 인식한다. `\x1b[>1c`를 쓰면 `1c`가 화면에 글자로 남아, 폭 계산이 맞아도 화면 단정이 어긋난다.

## 원인

- 원본 `width()`의 CSI 상태(`escSeq === 2`)가 `;`와 숫자만 파라미터로 받고 그 밖의 문자에서 시퀀스를 끊었다(폭 0으로 종료). `\x1b[?25l`의 `?`에서 끊기면 뒤 `25l`이 일반 글자로 폭 3이 된다.
- ECMA-48의 CSI 본문은 파라미터 바이트 0x30–0x3F(숫자·`:`·`;`·`<=>?`)와 중간 바이트 0x20–0x2F가 이어지다가 최종 바이트 0x40–0x7E에서 끝난다. 원본은 이 범위의 일부만 알았다.

## 탐지/회피

- 상태 2에서 0x20–0x3F를 이어가고 그 밖은 폭 0으로 끝낸다(현재 구현). 벤더 `tty.test.ts`(`\x1b[?25l50%`의 폭 3, `\x1b[?25h`·`\x1b[?7h`·`\x1b[1;2H` 폭 0)와 `print-above-raw.test.ts`("접두의 CSI 사설 시퀀스 폭")가 고정한다. 브라우저는 `apps/demo/e2e/checks/bg-output-check.mjs` B08(커서 열 14, 어긋나면 17)이다.
- `width()`를 바꾸면 사설 접두 CSI를 접두로 싣는 위 시험을 먼저 돌린다. 시험은 접두 `?`만 쓰거나, 다른 접두는 `Tty.calculatePosition`으로 폭만 확인한다(`VTerm` 화면으로 단정하지 않는다).
- BS·BEL은 폭 계산이 아니라 `packages/pyodide-core/src/terminal/output-tail.ts`가 정규화한다(BS 적용, BEL 등 나머지 C0 제거). OSC·DCS 등 CSI 밖 시퀀스와 8비트 C1은 폭 계산이 모른다.
