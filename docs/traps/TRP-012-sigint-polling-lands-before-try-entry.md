# TRP-012 눌림 뒤 첫 폴링이 `try` 진입 전에 떨어지면 `KeyboardInterrupt`가 `except` 바깥으로 나간다

- 상태: ACTIVE
- 적용 조건: 시험 프로그램이 눌림을 일으킨 뒤(스레드에 신호하는 `started()` 호출이나 직접 `press()`) `try: <루프> except KeyboardInterrupt:`로 잡으려는 모든 node·브라우저 시나리오.

## 오해하기 쉬운 신호

`press()`(또는 `started()`)를 `try:` 바로 앞 줄에 두면 대부분의 실행에서 통과한다. 다섯 번에 네 번 초록이고 다섯 번째에만 `expected false to be true`가 나기 때문에 "환경 탓"으로 넘기기 쉽다. 실패했을 때도 예외는 정상적으로 발생했고 중단 자체는 동작한 것이라 구현 결함처럼 보이지 않는다.

## 원인

눌림을 쓰는 것과 pyodide가 그것을 폴링하는 것 사이에 동기 경계가 없다. 폴링은 바이트코드 약 50개마다 일어나고 위상은 앞서 실행된 코드량에 따라 밀린다. 그래서 어떤 실행에서는 `press()` 호출이 돌아온 직후, `try` 블록에 진입하기 전의 명령에서 SIGINT가 처리된다. CPython의 `try`는 zero-cost라 진입 전 명령은 예외 테이블 범위 밖이고, 예외는 `except`를 그냥 지나쳐 올라간다.

## 탐지/회피

- 눌림을 일으키는 호출을 `try` **본문 첫 줄**로 옮긴다. 눌림 스레드를 쓸 때도 `started()`를 `try` 안에서 부른다.
- 같은 이유로 무한 루프를 쓰지 않는다. 눌림이 소실되거나 폐기되면 시험을 멈출 수 없다 — 상한 있는 루프(`for _ in range(10**7): pass`, `while started(): pass` + 시간 상한)를 쓴다.
- 시나리오가 예외를 잡았는지와 별개로 "화면/stderr에 트레이스백이 나갔는가"를 따로 세면, 이 현상이 일어난 시행을 통계로 구분할 수 있다.
