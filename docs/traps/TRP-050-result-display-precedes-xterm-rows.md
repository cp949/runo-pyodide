# TRP-050 결과 표시(React 상태)가 화면 행(xterm DOM)보다 먼저 보여, 결과를 본 직후 행을 읽으면 마지막 출력 행이 없다

- 상태: ACTIVE
- 적용 조건: 실행창(`?view=runner`) e2e가 `result` 표시가 채워진 직후 `.xterm-rows > div` 행을 읽어 전체를 대조하거나 "행에 X가 없다"를 판정할 때. 특히 실행 결말과 같은 시점에 찍힌 마지막 `print` 출력.

## 오해하기 쉬운 신호

- 결과가 `ok`인데 마지막 출력 행만 없어 출력이 유실된 것처럼 보인다. 다음 실행에서는 재현되지 않는다(경합).
- 부재 확인("행에 X가 없다")은 행이 아직 그려지지 않아 통과한다. 결함이 있어도 통과하므로 검출력이 없다.

## 원인

- 결과는 `run()` Promise → React 상태로 곧바로 DOM에 나오고, 출력은 xterm `write` → 버퍼 갱신 → DOM 렌더러의 rAF 갱신을 거친다. 출력 조각은 결말보다 먼저 도착하지만 화면 반영은 뒤질 수 있다.

## 탐지/회피

- 결과를 본 뒤 기대하는 마지막 출력 행을 `waitRow(...)`(조건 대기)로 기다린 뒤 전체 행을 대조한다(`docs/design/09-testing.md` 9.7 규칙 4). 부재 확인은 마커 배리어(9.7 규칙 3)로 한다. 예: `apps/demo/e2e/checks/runner-check.mjs`의 R06 마지막 단계(`waitResult` 뒤 `waitRow("'ok'")`).
