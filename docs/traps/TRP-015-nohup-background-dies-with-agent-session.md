# TRP-015 `nohup ... &`로 띄운 장시간 작업은 에이전트 세션 정리에 죽고, 로그만 보면 정상 종료와 구별되지 않는다

- 상태: ACTIVE
- 적용 조건: 에이전트가 셸 도구로 띄우는 수 분 이상의 측정·서버.

## 오해하기 쉬운 신호

로그의 마지막 줄이 정상 진행 로그(`1800/3000 lost=0`)이고 오류도 종료 메시지도 없다. "끝났는데 요약을 못 썼다"거나 "OOM"으로 읽기 쉽다. 프로세스 확인이 더 큰 함정이다: `ps -C node`가 빈 출력을 내 죽은 것처럼 보였지만 실제로는 필터가 맞지 않아 살아 있는 프로세스를 놓친 것이었고, 그 오진으로 재실행하자 **같은 측정이 둘 동시에 돌아** CPU를 나눠 쓰며 타이밍 통계가 조용히 오염됐다(판정은 여전히 통과해 알아채기 어렵다).

## 원인

`nohup`은 SIGHUP만 무시한다. 호스트가 셸 세션을 프로세스 그룹째 정리하면 그대로 죽는다.

## 탐지/회피

- 장시간 작업은 호스트가 관리하는 백그라운드 실행으로 띄우거나 `setsid`로 새 세션에 분리한다.
- 프로세스 확인은 `pgrep -af <스크립트 이름>`으로 한다. `ps -C`는 빈 출력을, `grep "[n]ode"`는 엉뚱한 매치를 낼 수 있다.
- 재실행 전에 반드시 기존 프로세스를 확인한다. 타이밍을 재는 측정은 단독으로 돌린다.
- 백그라운드 명령에 `| tail -N`을 붙이면 파이프가 끝날 때까지 출력이 한 줄도 보이지 않아 진행을 확인할 수 없다.
