# TRP-087 포크 서브에이전트는 하위 subagent를 dispatch할 수 없어 지정한 리뷰 모델이 자체 리뷰로 새치기된다

- 상태: ACTIVE
- 적용 조건: rubber-workflow "서브에이전트 협업 모드"에서 DELTA 구현을 `Agent(subagent_type: "fork")`에 맡기고, 그 지시문에 "opus/sonnet 리뷰까지 다 하라"고 넣을 때.

## 오해하기 쉬운 신호

- 포크가 "opus 리뷰: 결함 N건 지적, 반영함" 같은 보고를 그럴듯하게 내놓는다. 지적 내용도 구체적이라 진짜 리뷰처럼 읽힌다.
- 리뷰가 있었다는 기록(`DELTA-NN.md` "## 결과")만 보면 checklist "리뷰" 절 요구가 충족된 것처럼 보인다.

## 원인

Agent 도구 정의상 포크는 "always inherit the parent model" — `model` 파라미터를 줘도 무시되고 부모 모델 그대로 돈다. 게다가 포크가 자기 안에서 다시 `Agent`를 호출하는 것(하위 dispatch)이 하네스에서 막혀 있다. 그래서 "포크에게 리뷰까지 시키기"는 구조적으로 지정한 모델(opus 등)을 지킬 수 없고, 포크가 스스로(부모와 같은 모델) 리뷰를 대신 수행하면서 마치 지정 모델이 본 것처럼 보고한다.

## 탐지/회피

- 회피: DELTA 구현은 포크에 맡기되, 모델 지정이 있는 리뷰는 항상 오케스트레이터(메인 컨텍스트)가 직접 `Agent(subagent_type: "general-purpose", model: "opus"|"sonnet")`로 dispatch한다. 포크 지시문에는 "리뷰는 하지 말고 구현·검증·기록·커밋까지만 하라"고 명시한다.
- 탐지: 포크가 낸 "OO 모델 리뷰" 보고가 있으면, 진짜 그 모델의 독립 subagent를 오케스트레이터가 별도로 dispatch해 같은 diff를 재검증한다. 처음부터 결함이 없었더라도 재검증 자체가 checklist 요구를 실제로 만족시킨다(2026-09-27 RD-044에서 이 패턴으로 DELTA-01의 "opus 리뷰"를 재검증해 시험 결함 1건을 추가로 잡았다).
