# TRP-014 눌림 스레드를 `Atomics.wait`로 재우면 송신기의 재전송 점검이 죽고 "소실 0"이 저절로 나온다

- 상태: ACTIVE
- 적용 조건: 별도 스레드(`node:worker_threads`)에서 main의 눌림 송신기(`createInterruptSender`)를 그대로 써서 소실·복구를 재는 하니스. 송신기를 쓰지 않고 `signalInterrupt`만 쓰는 역할 스크립트는 해당 없다 — 그 역할에 송신기를 넣는 순간 해당된다.

## 오해하기 쉬운 신호

측정이 정상 종료하고 소실 0, 재전송 히스토그램이 `{0: N}`으로 깨끗하게 나온다. "소실이 없어서 재전송도 없었다"로 읽히지만 실제로는 재전송 타이머가 한 번도 돌지 못한 것이다. 감시견이 라운드를 구조하면 측정 자체는 끝까지 진행되므로 로그에도 이상이 없다.

## 원인

송신기의 5ms 점검은 `setTimeout`으로 예약된다. `Atomics.wait`는 스레드를 통째로 막으므로 이벤트 루프가 돌지 않고 예약된 콜백이 실행되지 않는다. 눌림 사이를 `Atomics.wait`로 재우는 하니스에서는 재전송 경로 전체가 죽은 코드가 된다.

## 탐지/회피

- 스레드가 송신기를 쓰면 대기를 `Atomics.waitAsync`와 `setTimeout`으로 만들고 마지막 1~2ms만 스핀해 정밀도를 맞춘다.
- 재전송 히스토그램이 전부 0이면 "소실이 없었다"로 결론내기 전에 **소실을 강제하는 변이**(첫 SIGINT 쓰기를 삼킨다)로 재전송이 실제로 일어나는지 먼저 확인한다. 그 변이에서 복구가 100%이고, 재전송 상한을 0으로 둔 변이에서 소실이 100%여야 하니스가 양쪽을 본다는 뜻이다.
