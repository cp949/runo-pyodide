# TRP-030 SIGINT 폴링 위상 때문에 무관한 변경이 경합 시험의 자연 재현율을 0%↔67%로 바꾼다

- 상태: ACTIVE
- 적용 조건: 실제 pyodide + interrupt buffer로 "SIGINT가 어느 bytecode 위치에서 처리되는가"에 걸린 경합을 재현·검증할 때.
  특히 수정 효과를 자연 재현율(반복 N회 실패 0)로 판정할 때, 시험 조립·해체·앞선 시험의 Python 실행량을 바꿀 때.

## 오해하기 쉬운 신호

- 시험 조립의 무관한 순서 변경 하나(`sigint-setup.ts`의 `restoreRunSync`를 SIGINT 버퍼 해제 뒤로 이동)로
  `sigint-handler-idle.test.ts` 단독 재현율이 20/30 → 0/30이 됐다. "고쳐졌다"로 읽기 쉽지만 경합은 그대로였다(경합 지점
  주입 5/5 재현).
- CPU 부하(node 바쁜 루프 12개)를 줘도 재현율이 오르지 않는다(0/20, 실행 시간은 7.3s → 10s로 늘어남). "실시간 타이밍
  문제가 아니다 → 경합이 없다"로 오판하기 쉽다.
- 반대로 무관한 변경이 위상을 옮겨 멀쩡하던 시험이 갑자기 깨지면 그 변경을 회귀로 오판한다(pyodide-core 추출처럼 조립
  코드를 옮기는 작업에서).

## 원인

- pyodide는 interrupt buffer를 eval breaker 확인 N회마다 한 번 폴링한다(추정: `_Py_emscripten_signal_clock`, CPython 소스
  미확인. TRP-012의 "바이트코드 약 50개마다"와 같은 성질). SIGINT가 처리되는 bytecode 위치는 눌림 시각보다 그때까지 실행한
  확인 횟수의 위상으로 정해진다.
- 앞선 시험·해체·조립이 실행한 Python 양이 바뀌면 위상이 바뀐다. 실측: 같은 시나리오에서 눌림 전에
  `for _ in range(k): pass`를 더하면 `InvalidStateError` 비율이 k=10 0/20, k=0 3/20, k=33 6/20, k=34 9/20.
- 실시간 부하는 폴링 횟수를 바꾸지 않아 재현율에 거의 영향이 없다.

## 탐지/회피

- 경합 수정의 판별은 자연 재현율 대신 경합 지점에 `press(); signal.raise_signal(signal.SIGINT)`를 주입한 결정적 시험으로
  한다(예: `sigint-handler-idle.test.ts`의 `asyncio 콜백 경합 지점에서 처리된 SIGINT(주입)` 묶음). 수정 전 코드로 되돌려
  결정적으로 실패하는지 확인한다.
- 자연 경로 확인이 필요하면 눌림 전 실행량 k를 훑어(위상 스윕, 예: k=0..59 ×3) 재현율이 높은 k를 골라 그 k에서 N회 돌린다.
  한 위상의 "N회 실패 0"은 판별력이 없다.
- 간헐 실패 이슈가 "요즘 안 난다"로 닫히려 하면, 그 사이 조립·해체 코드 변경이 있었는지 먼저 본다.
