# TRP-009 한 작업 트리에서 에이전트 둘이 동시에 일하면 변이 검사와 시험이 서로를 오염시킨다

- 상태: ACTIVE
- 적용 조건: 한 저장소·한 브랜치에서 에이전트가 둘 이상 동시에 작업하면서 변이 검사기(소스를 제자리에서 변조한 뒤 시험하고 복원하는 도구)나 임시 디버그 계측, 커밋을 쓸 때.

## 오해하기 쉬운 신호

- 시험이 1건만 실패하고 재실행하면 통과한다. 소스 결함처럼 보이지만 그 순간 다른 에이전트의 변이가 같은 파일에 적용돼 있었다.
- 소스 파일에 쓴 적 없는 디버그 코드가 나타났다가 사라진다.
- `git log`에 내가 만들지 않은 커밋이 생기고 내가 만든 미커밋 파일이 그 커밋에 들어간다. 검증 폴더의 변이 스펙이 같은 이름으로 덮어써진다.
- 파일 sha256 대조가 갑자기 어긋난다.

## 원인

변이 검사기는 작업 트리의 실제 소스를 바꿨다가 복원하고 vitest는 같은 파일을 읽는다. 두 실행이 겹치면 한쪽의 변이가 다른 쪽의 시험 입력이 된다. 브랜치·index·체크리스트·검증 폴더도 공유되고, 이어받기 절차는 "마지막 DELTA의 결과가 비어 있으면 그 DELTA부터"라서 진행 중인 DELTA를 다른 에이전트가 이어받아 같은 DELTA를 동시에 끝낼 수 있다.

## 탐지/회피

- 회피: 에이전트마다 `git worktree`로 작업 트리를 분리하거나 한 번에 한 에이전트만 진행한다. 변이 검사와 양성 대조는 다른 에이전트가 시험·서버를 돌리지 않을 때만 한다. 커밋은 `git add <경로>`로 자기 파일만 지정한다.
- 탐지: 작업 시작 시 `ps -eo pid,args | grep -E "claude|codex|vitest|mutate"`로 후보를 찾고 각 프로세스의 `readlink /proc/<pid>/cwd`가 이 저장소인지 본다. 변이·시험 전후로 대상 파일 sha256을 대조한다. `git log -3 --format='%h %ad %s'`로 낯선 커밋을 확인한다.
