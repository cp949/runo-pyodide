# TRP-075 핸들러 클로저 상태 해제 줄은 시험마다 새 클로저라 결말 stderr가 같으면 변이가 생존한다

- 상태: ACTIVE
- 적용 조건: `setupConsoleRunner`(`packages/pyodide-repl/src/test/sigint-setup.ts`)로 SIGINT 핸들러 클로저 상태(`converting`·`pending`·`woken` 등)의 해제·초기화 로직을 변이 검사할 때, 핸들러에 클로저 상태를 새로 더할 때.

## 오해하기 쉬운 신호

- 해제 줄을 지운 변이(예: `run_sync` 래퍼 `finally`의 `converting = False` 제거)가 새 시험 3건 모두 통과한다. 시험이 통과하므로 "해제는 필수가 아니다"나 "동등 변이"로 적기 쉽다.
- 실제로는 표시가 남으면 뒤 `run_sync`의 눌림이 다른 경로로 처리되는 결함이다. 다만 그 차이가 결말 stderr에는 드러나지 않는다.

## 원인

- `setupConsoleRunner`가 시험마다 `sigint-handler.py`를 새로 설치해 클로저 상태가 시험 사이에 이월되지 않는다. 한 시험 안에서 표시가 남아도 그 시험은 `run_sync`를 한 번만 부르고 끝난다.
- 표시가 남았을 때의 차이(눌림이 미룬 깨우기 대신 다른 규칙으로 처리됨)는 결말이 같은 표준 트레이스백이라 stderr 단언으로는 구분되지 않는다.

## 탐지/회피

- 같은 세션에서 앞선 `run_sync`를 한 번 지난 뒤(표시를 내려야 하는 경로를 실행한 뒤) 다음 `run_sync`의 Task 생성 전에 눌림을 주입하는 시험을 별도로 둔다. 결말이 같아도 달라지는 관찰 가능한 사건(awaitable 시작 여부)을 단언한다. `sigint-handler-idle.test.ts`의 `앞선 run_sync가 끝난 뒤 Task 생성 전에 처리된 SIGINT는 awaitable을 시작하지 않고 표준 트레이스백만 남긴다`가 그 시험이다. 이 시험을 더하기 전에는 해당 변이가 생존했고(5/6), 더한 뒤 6/6이 됐다.
- 클로저 상태를 더하거나 해제 줄을 바꾸면 그 줄을 지운 변이를 만들어 시험이 실패하는지 확인한다. 생존하면 동등 변이로 결론짓기 전에 위처럼 상태 이월을 만드는 시험이 있는지 본다.
