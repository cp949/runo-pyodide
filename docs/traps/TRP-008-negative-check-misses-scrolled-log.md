# TRP-008 "로그가 없다"는 브라우저 확인을 뷰포트만 훑어 하면 화면 밖으로 밀려난 로그를 놓친다

- 상태: ACTIVE
- 적용 조건: 브라우저 하니스가 "이 문자열이 화면에 없다"를 `.xterm-rows`(뷰포트 24행)에서 후속 출력 뒤에 판정할 때. 트레이스백처럼 여러 행짜리 stderr 로그가 대상일 때.

## 오해하기 쉬운 신호

- 원인을 되살려(수정을 제거해) 봐도 확인이 통과해 "브라우저에서는 누출이 없다"로 읽힌다. 실제로는 로그가 나왔고 뒤이은 출력에 밀려 뷰포트 위로 스크롤됐다.
- 브라우저 콘솔 검사도 0건이다. Python stderr는 콘솔이 아니라 터미널로 간다.

## 원인

문법 오류 `ConsoleFuture`의 예외를 회수하지 않으면 사이클 GC 때 `ConsoleFuture exception was never retrieved`와 24행 이상의 트레이스백이 stderr로 나온다. 확인이 `gc.collect()`를 세 번 돌린 뒤 뷰포트를 읽었고 로그는 첫 `gc.collect()`의 출력이라 이미 스크롤된 뒤였다.

## 탐지/회피

- 회피: 화면을 지우고(Ctrl+L) 동작 한 번 직후의 행 목록 전체를 정확히 단언한다(`>>> gc.collect()` / `<숫자>` / `>>>` 3행). "없다"를 문자열 부재가 아니라 "정확히 이 행들"로 판정한다.
- 탐지: 원인을 되살리는 양성 대조(수정 제거)에서 확인이 실패하는지 본다. 통과하면 확인이 약한 것이다.
