# TRP-018 `pkill -f`가 자기 셸 명령줄을 매치해 뒤 단계(원복)를 날린다

- 상태: ACTIVE
- 적용 조건: 한 셸 호출 안에서 `pkill -9 -f "<패턴>"`을 쓰고 그 뒤에 원복·정리 단계를 이어 붙일 때.

## 오해하기 쉬운 신호

- `pkill` 자체는 성공한다. 그런데 뒤에 붙인 `git checkout --`·`git status`가 **출력 없이 사라진다.**
- 명령이 실패한 것처럼 보이지 않는다(에러 메시지가 없다). 소스가 변조 상태로 남은 것을 놓치기 쉽다.
- 다음 확인·시험이 이상한 결과를 내는데 원인이 두 단계 앞의 자살한 셸이다.

## 원인

`pkill -f`는 프로세스의 **명령줄 전체**를 본다. 에이전트가 실행하는 `bash -c '… pkill -9 -f "vitest/dist/workers/forks.js" …'`의 명령줄에는 패턴 문자열이 그대로 들어 있으므로 셸 자신이 매치되어 `SIGKILL`을 받는다.

## 탐지/회피

- 패턴에 대괄호를 넣어 자기 매치를 깬다(정규식으로는 같은 것을 가리키지만 명령줄 문자열과는 다르다).

```bash
pkill -9 -f 'vitest/dist/workers/fork[s].js'
```

- 또는 `pgrep`로 PID를 먼저 뽑아 `kill`에 넘긴다(`pgrep`에도 같은 대괄호 트릭을 쓴다).
- 원복처럼 반드시 돌아야 하는 단계는 `pkill`과 **다른 호출**로 떼어 둔다.
