# TRP-059 재그리기 콜백의 앵커 갱신을 빼도 화면 시험 대부분이 통과한다 — "동등 변이"로 적기 쉽다

- 상태: ACTIVE
- 적용 조건: 벤더 `Readline`의 재그리기 콜백(`printAbove`·`printAboveRaw`, `read()`)에서 `Tty.anchorRow`를 갱신하는 코드를 바꾸거나 그 변이 검사를 할 때.

## 오해하기 쉬운 신호

- `anchorRow = term.buffer.active.cursorY` 줄을 지운 변이가 화면·스크롤백 시험 153개를 모두 통과해 살아남는다. 화면 모양이 같으니 "관찰 가능한 차이 없음(동등 변이)"으로 판정하기 쉽다.

## 원인

콜백은 `resetLayout()` 뒤 `refresh()`를 부르므로 `refreshLine` 3단계의 위로 올라가는 양(`physicalRow - anchorRow`)이 0이 되어 현재 물리 커서에서 바로 그린다. 이후 재그리기도 레이아웃 기준 상대 이동이라 앵커 값이 틀려도 자연 스크롤로 같은 모양이 된다. 앵커의 절대값은 2단계(미리 스크롤할 양 계산)에서만 쓰이고, 옛 앵커가 0이거나 실제 행과 같으면 결과가 같다.

## 탐지/회피

- 옛 앵커가 0보다 크고 실제 행보다 작은 상황을 만든다: 프롬프트를 1행 이후에 두고, 출력 2행으로 커서를 내린 뒤, 입력을 화면보다 크게 키워 2단계 스크롤을 일으키고 출력 행이 지워지지 않고 스크롤백으로 올라가는지 본다. 예: `packages/xterm-readline/src/print-above-raw.test.ts` "다시 그린 뒤 입력이 화면보다 커지면 출력 행은 스크롤백으로 올라가고 지워지지 않는다".
- 앵커 관련 변이는 이런 시험 없이 동등 변이로 적지 않는다.
- 실제 xterm의 맨 아래 행 스크롤과 앵커 일치는 스텁 모델만으로 확정하지 않고 브라우저에서 맨 아래 행 프롬프트 셀로 확인한다(`apps/demo/e2e/checks/bg-output-check.mjs` B06).
