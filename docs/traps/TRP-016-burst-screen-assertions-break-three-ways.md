# TRP-016 연타 Ctrl+C의 화면 판정은 행 감김·스크롤 아웃·프롬프트 재그리기에 세 번 깨진다

- 상태: ACTIVE
- 적용 조건: 실행 중 Ctrl+C를 여러 번 누르고 화면 텍스트로 결과를 판정하는 브라우저 확인(80×24 고정 터미널).

## 오해하기 쉬운 신호

화면 행 목록을 눈으로 보면 트레이스백이 멀쩡히 한 번 있는데 `rows().filter(r => r.includes("Traceback (most recent call last):"))`가 0을 돌려준다. 판정이 실패(DIRTY)로 나오므로 구현 결함을 의심하게 되지만 셋 다 하니스 문제다. 반대로 스크롤 아웃된 시행을 "트레이스백 0"으로 통과시키면 진짜 결함을 놓친다.

## 원인

1. **행 감김**: `^C` 30개(60칸)에 트레이스백 머리글(34칸)이 이어지면 80칸을 넘어 `Traceback (most rece` / `nt call last):`로 나뉜다. 행 단위 `includes`는 찾지 못한다.
2. **스크롤 아웃**: 실행이 끝난 뒤 도착한 눌림은 활성 읽기로 가 벤더 `Readline`이 `^C\r\n` + 프롬프트를 한 행씩 다시 그린다(정상 동작). 그 행이 24행 뷰포트를 채우면 트레이스백이 밀려 나간다. xterm 스크롤백은 DOM에 없어 행 조회로는 볼 수 없다.
3. **꼬리가 남은 프롬프트**: 눌림마다 `^C`가 꼬리에 쌓여 프롬프트가 `^C…^C>>> `가 된다. Ctrl+L은 그 행을 그대로 맨 위에 다시 그리므로 "첫 행이 `>>>`"를 기다리는 화면 지우기가 시간 초과한다.

## 탐지/회피

- 트레이스백 수는 행 단위가 아니라 **이어붙인 화면**(`rows().join("")`)에서 센다.
- 프롬프트 재그리기 행 수(`/^>>> \^C$/`)를 함께 기록해 "0이 스크롤 아웃인지 진짜 없음인지" 구분한다. 결정적으로 실패로 볼 수 있는 것은 "2 이상"과 "재그리기가 없는데 0"뿐이다.
- 시행을 시작하기 전과 후속 실행 전에 마지막 행이 `>>>`가 아니면 빈 Enter로 프롬프트를 정리한 뒤 화면을 지운다.
